## MODIFIED — 2.96.6 提案起点 `baseRef`

- `openlogos change <slug>` 写 guard 时，若项目是已有提交的 git 仓库，写入 `baseRef`（当时 `HEAD` 的 40 位提交号）；非 git 或尚无提交时不写该字段。
- 目前只有 `openlogos change`（含 `openlogos next` 问即建时对它的调用）写 guard；它因提案已存在等原因拒绝创建时不重写 guard，已有 `baseRef` 原样保留。今后新增的 guard 写入者（含宿主）必须保留已有 `baseRef`。
- 旧 guard 缺字段时，只在模块范围已启用的项目里有影响：回落全量（`base_ref_missing`）。
- 检查 `baseRef` 与计算差异只读本地对象库、有时限（§2.111）：`baseRef` 的提交对象本地不存在、或检查它的调用超过时限时，回落全量（`base_ref_unreachable`）；提交在但差异计算读不到所需的文件内容、或收集改动文件的调用超过时限时，回落全量（`diff_failed`）。两种情形都不从远端取回对象。

## ADDED — 2.111 验收期间的 git 调用只读本地（verify-git-local-only）

> 来源变更：verify-git-local-only（Team 需求池 openlogos #8；决策 C01、C02）。对应需求「S13 验收期间的 git 调用只读本地验收补充」AC-VERIFY-LOCAL-01～09。本节不新增原因代码、JSON 字段与配置项。

### 2.111.1 适用范围与调用方边界

- **适用**：`openlogos verify` 自己启动的 git 子进程，提案级、发布级（`--release`）与发布查询（`--release --check`）都在内：
  - 判断项目是否 git 仓库；
  - 检查提案起点提交是否存在（§2.96.6）；
  - 收集改动文件：差异计算与列出未跟踪文件（§2.96.3）；
  - 读取提案起点中的共享验收配置文件内容（§2.96.3.1）；
  - 读取合并基线记录的合并前内容，及为此枚举本地对象（§2.109.5）；
  - 发布级验收与发布查询中的全部 git 调用，含解析 `--commit` 指定的提交（§2.109.11、§2.109.12）；
  - 提案级验收为验收历史读取提交号与工作区状态（§2.104.3）。发布级验收不在写历史时重新读取，见 §2.111.5。
- **不适用**：
  - 测试命令（`verify.pre_run_command` 等）自己执行的 git；
  - `openlogos smoke`、merge、deploy、branch sync 及其他命令的 git 调用；
  - `openlogos smoke` 写历史记录时读取提交号与工作区状态的调用——它与 verify 共用同一个读取函数，该函数及其时限不变（§2.111.5）。

### 2.111.2 三项约束

适用范围内的每一个 git 子进程都同时满足：

1. **不连接远端、不取回对象**：把传输协议白名单置空（环境变量 `GIT_ALLOW_PROTOCOL` 为空串），并设置禁用按需取回的开关（`GIT_NO_LAZY_FETCH=1`）。
   - 识别该开关的 Git（2.45 起）：缺对象时直接以读不到对象失败，不启动取回。
   - 不识别该开关的 Git：可能启动一个 fetch 子进程，但在建立传输之前即被白名单拒绝。
   - 仓库或用户配置中放行某种协议（如 `protocol.file.allow=always`）不改变上述结果：环境变量给出的白名单优先。
2. **不弹出凭据或终端提示**：`GIT_TERMINAL_PROMPT=0`。
3. **有时限**：每次调用单独计时，超过即终止该子进程并按该调用失败处理。
   - 没有既有时限的调用，缺省 60 秒；
   - 已有时限的调用保留原值：发布级验收与发布查询的 git 调用 60 秒；为验收历史读取提交号 10 秒、读取工作区状态 30 秒。
   - 「终止」指子进程确实退出：调用返回时该子进程已不存在，不遗留仍在等待的 git 进程。
   - 时限没有用户配置项。执行入口保留一个仅供测试使用的时限覆盖，用于在不等待 60 秒的情况下验证真实的超时终止。

三项约束通过一个共用的执行入口实现，适用范围内的调用都经它执行；`affected-scenarios.ts` 读取合并前内容时自行设置开关的写法改为调用这个入口，行为不变（§2.109.5，含不识别该开关的 Git 上按本地对象清单逐个判断）。

### 2.111.3 可观测结果的口径

「不连接远端」以下面两条为准，二者都必须成立：

- 没有与任何远端建立传输（远端一侧没有收到请求）；
- 本地对象库没有新增对象（松散对象与 pack 都没有新增）。

「是否出现过 fetch 子进程」不是判据：不识别 `GIT_NO_LAZY_FETCH` 的 Git 上，缺对象时会出现一个被启动又被拒绝的 fetch 子进程，这符合本节的约束。测试对这两类观测分开断言。

### 2.111.4 调用失败后的结果

缺的对象不同、调用方不同，落入的既有结果不同；本节不改变任何一种。

| 失败的调用 | 失败方式 | 按模块限定范围（§2.96） | 分层验收（§2.109.7） |
|---|---|---|---|
| 检查提案起点提交 | 提交对象本地不存在；或调用超过时限 | 回落全量，`base_ref_unreachable`；不再执行差异计算 | 扩大到全量，`base_ref_unavailable` |
| 收集改动文件（差异计算、列出未跟踪文件） | 起点提交在，但读不到所需的文件内容；或调用超过时限；或其他失败 | 回落全量，`diff_failed` | 扩大到全量，`base_ref_unavailable` |
| 读取提案起点中的共享验收配置文件内容 | 读不到内容；或调用超过时限 | 按整文件变化处理（§2.96.3.1「无法判断」），回落全量，`shared_config_changed` | 扩大到全量，`shared_path_changed` |
| 读取合并前内容 | 本地读不到；或调用超过时限 | —— | 该测试用例文档按文件名记为 delta 触及（§2.109.5） |

- **超时按失败的那一次调用归类**：原因代码与该调用其他失败方式相同。起点提交实际存在、但检查它的调用先超时时，原因是 `base_ref_unreachable`，不是 `diff_failed`。
- **发布查询**（`openlogos verify --release --check --commit <sha>`）：`--commit` 指定的提交本地解析不出（含本地不存在该提交对象、调用超过时限）时，照旧以 `RELEASE_CHECK_COMMIT_INVALID` 拒绝，退出码 2。该入口只查询既有结论，不回落、不执行任何用例。
- **发布级验收**（`openlogos verify --release`）本来就执行全量，没有「回落」；其 git 调用失败时的拒绝与结论按 §2.109.11 既有规则。
- **说明文字**：
  - 因本地缺少对象而失败时，`detail` 在既有文字之后写明「本地缺少对象，验收不从远端取回」；
  - 因超过时限而失败时，`detail` 写明超时与时限秒数；
  - 原因代码不变。读取提案起点配置内容失败时沿用 §2.96.3.1 既有的 `<路径>（提案起点中的内容读取失败）`。
- **门禁**：回落或扩大只改变验收集合，本身不直接置 FAIL，也不保证 PASS。门禁按最终集合与既有的门禁规则判定，原因优先级不变（§2.106.7、§2.109.10）。
  - 其他门禁条件都满足、没有优先级更高的原因时：全部通过则 PASS；原本不在集合内、因扩大而执行的用例失败时，按 `failed_cases` 判 FAIL。
  - 同时存在优先级更高的原因时（如测试变更集无效、主链路用例偶发），`gate.reason` 取那个原因，与没有回落时相同。
  - 测试入口因用例失败而非零退出、且结果中有可采信的失败记录时，原因是 `failed_cases`，不是 `pre_run_failed`；只有命令失败而看不到可采信的失败记录时才按 `pre_run_failed`。这条既有区分（`spec/test-results.md`「测试入口的义务」第 2 条）不因回落或扩大改变。

### 2.111.5 验收历史与 smoke

- 读取提交号与工作区状态的函数由 verify 与 smoke 的历史记录共用，带 10 秒、30 秒时限。**该函数不改。**
- **提案级验收**写历史记录时，先经共用执行入口（保留 10 秒、30 秒时限）读出提交快照，再把快照传给历史记录；不经由那个共用函数的缺省读取。这只替换原本使用缺省读取的提案级路径。
- **发布级验收**的历史记录继续使用运行开始时固定的提交（§2.109.11）：前置检查固定提交 A 并传给历史记录，收尾另行复核 HEAD 与工作区（任一有变化即按既有发布门禁判 `release_commit_changed`）。写历史时**不重新读取**提交号——测试期间 HEAD 变为 B 时，这次运行仍然记在 A 上。本节只让发布级的前置检查与收尾复核这些 git 调用经共用执行入口执行（既有 60 秒时限不变），不改变提交归属。
- smoke 写历史记录时继续使用该函数的缺省读取：环境变量、时限与结果都和 0.16.29 相同。

### 2.111.6 兼容性与已知限制

- 所需对象在本地齐全、有关调用都在时限内正常完成的仓库：验收范围、原因、执行的命令与用例、门禁结论与 0.16.29 相同；原有条件允许缩小范围时照常缩小。传输与提示两项约束对不需要远端的读取没有可见影响。
- 对象齐全但调用超过时限：0.16.29 的范围计算没有时限，会一直等到调用完成；0.16.30 起到时终止，并按 §2.111.4 表中**该调用所在的那一行**处理。这是对象齐全时唯一的一类行为差异。
  - 检查提案起点提交、或收集改动文件的调用超时：回落或扩大到全量；
  - 读取提案起点中的共享验收配置内容超时：无法证明只有无关字段变化，按整文件变化处理——按模块限定范围回落全量（`shared_config_changed`），分层验收扩大到全量（`shared_path_changed`）；
  - 读取某份测试用例文档的合并前内容超时：只有那一份文档按文件名记为 delta 触及，其他文档照常比较，其他场景仍可排除——不触发全量。
- 部分克隆且本地缺对象的仓库：0.16.29 及之前会联网取回后按范围验收；0.16.30 起不联网，按 §2.111.4 回落或扩大到全量。只会多跑，不会少跑。
- **已知限制**：不识别 `GIT_NO_LAZY_FETCH` 的 Git 上靠传输协议白名单拦截。这条路径只在 Git 2.48.1 上以「只设白名单、不设该开关」的方式验证过，没有在真实的旧版 Git 上执行。
- **已知限制**：部分克隆下想保持按范围验收，需要先让提案起点的提交与相关文件内容在本地齐全；verify 不代为取回。
