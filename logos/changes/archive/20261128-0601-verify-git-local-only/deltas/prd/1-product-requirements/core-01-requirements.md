## ADDED — S13 验收期间的 git 调用只读本地验收补充（verify-git-local-only）

> 来源：Team 需求池 openlogos #8（决策 C01、C02）。规则权威见功能规格 §2.111。本补充只约束 `openlogos verify` 自己启动的 git 调用，不改变任何既有的原因代码、JSON 字段与退出方式。

### 场景定义

- **触发条件**：项目的 git 仓库本地缺少一部分对象，由远端按需提供（部分克隆等）。`openlogos verify` 计算验收范围时要读取提案起点的提交与其中的文件内容；0.16.29 及之前，这些读取会让 git 访问远端并把取回的对象写进本地对象库，且没有时限，远端无响应时验收一直挂住。
- **用户价值**：
  - 验收是只读操作：不联网，不改动本地对象库，不会无限等待。
  - 本地读不到所需对象时，验收按既有规则回落或扩大到全量，并说明原因是本地缺少对象。只会多跑，不会少跑。
  - 对象齐全的仓库不受任何影响。
- **优先级**：P2
- **主路径**：verify 启动的每一个只读 git 子进程都禁止远端传输、禁止取回对象、禁止弹出凭据提示，并带时限；调用失败后，按失败的那一次调用落入既有的结果。

### 定义

| 概念 | 定义 |
|---|---|
| 验收期间的 git 调用 | `openlogos verify`（提案级与发布级，含 `--release --check`）自己启动的 git 子进程：判断是否 git 仓库、检查提案起点提交、收集改动文件、读取提案起点中的配置文件内容、读取合并前内容、解析发布查询指定的提交、读取提交号与工作区状态。测试命令自己执行的 git 不在此列 |
| 不连接远端 | 没有与任何远端建立传输，本地对象库没有新增对象。旧版 Git 可能启动一个随即被拒绝的 fetch 子进程，这不算连接远端 |
| 时限 | 每次调用单独计时，超过即终止并按该调用失败处理。没有既有时限的调用缺省 60 秒；已有时限的调用保留原值 |
| 缺失对象的位置 | 本地缺的是提案起点的提交对象，还是起点提交之下的文件内容。位置不同，落入的既有结果不同 |

- 本补充不提供任何配置项。
- `openlogos smoke`、merge、deploy、branch sync 等其他命令的 git 调用不在范围内。

### 验收条件

#### AC-VERIFY-LOCAL-01：缺文件内容时不连接远端，回落或扩大到全量
- **GIVEN** 仓库的远端可以按需提供对象；本地有提案起点的提交，但缺少差异计算要读的文件内容。分别为：按模块限定范围已启用；分层验收已开启
- **WHEN** 执行 `openlogos verify --format json`
- **THEN** 没有与远端建立传输，本地对象库没有新增对象；前者回落全量，`fallback_reason.code` 为 `"diff_failed"`；后者扩大到全量，原因 `base_ref_unavailable`；两者的 `detail` 都写明是本地缺少对象、验收不从远端取回

#### AC-VERIFY-LOCAL-02：缺起点提交对象时不连接远端，判为起点不可达
- **GIVEN** 提案起点的提交对象本地不存在，远端可以提供；按模块限定范围已启用或分层验收已开启
- **WHEN** 执行 `openlogos verify --format json`
- **THEN** 没有与远端建立传输，对象库不变；按模块限定范围回落全量，`fallback_reason.code` 为 `"base_ref_unreachable"`；分层验收扩大到全量，原因 `base_ref_unavailable`；不执行差异计算

#### AC-VERIFY-LOCAL-03：发布查询指定的提交本地不存在时照旧拒绝
- **GIVEN** `--commit` 指定的提交本地不存在，远端可以提供
- **WHEN** 执行 `openlogos verify --release --check --commit <sha> --format json`
- **THEN** 没有与远端建立传输，对象库不变；仍以 `RELEASE_CHECK_COMMIT_INVALID` 拒绝，退出码 2；不回落、不执行任何用例

#### AC-VERIFY-LOCAL-04：调用有时限，超时按失败的那一次调用归类
- **GIVEN** 分别为：检查提案起点提交的调用超过时限（起点提交实际存在）；收集改动文件的调用超过时限
- **WHEN** 执行 `openlogos verify --format json`
- **THEN** 超时的调用被终止，验收继续；前者 `fallback_reason.code` 为 `"base_ref_unreachable"`，且不再执行差异计算；后者为 `"diff_failed"`；分层验收中二者的原因都是 `base_ref_unavailable`；`detail` 都写明超时

#### AC-VERIFY-LOCAL-05：回落之后门禁按实际结果判定
- **GIVEN** 因 AC-VERIFY-LOCAL-01、02 或 04 回落或扩大到全量；其他门禁条件都满足、没有优先级更高的门禁原因（如测试变更集无效、主链路用例偶发）；分别为：全部自动化用例通过；原本不在验收集合内的一条用例失败
- **WHEN** 执行 `openlogos verify --format json`
- **THEN** 前者 `gate.result` 为 `"PASS"`；后者为 `"FAIL"`，`gate.reason` 为 `"failed_cases"`
- 回落或扩大只改变验收集合，本身不直接置 FAIL，也不保证 PASS；门禁按最终集合与既有的门禁规则及原因优先级判定。同时存在优先级更高的原因时（例如一条主链路用例首跑失败、复跑通过），结论取那个原因，与没有回落时相同

#### AC-VERIFY-LOCAL-06：对象齐全的仓库行为不变
- **GIVEN** 验收要读的对象在本地齐全；有关的 git 调用都在各自的时限内正常完成；按模块限定范围已启用或分层验收已开启，且按 0.16.29 的规则本来可以缩小范围
- **WHEN** 执行 `openlogos verify --format json`
- **THEN** 验收范围、原因、执行的命令与用例、门禁结论与 0.16.29 相同；仍能正常缩小范围
- 对象齐全但**检查提案起点提交或收集改动文件**的调用超过时限时不适用本条，按 AC-VERIFY-LOCAL-04 处理：0.16.29 没有时限、会等到调用完成后缩小范围，0.16.30 起到时终止并回落全量
- 其余调用超过时限时，按该调用的既有规则处理：
  - 读取提案起点中的共享验收配置内容超时：无法证明只有无关字段变化，按整文件变化处理——按模块限定范围回落全量（`shared_config_changed`），分层验收扩大到全量（`shared_path_changed`）；
  - 读取某份测试用例文档的合并前内容超时：只有那一份文档按文件名记为 delta 触及，其他场景仍可排除，不因此扩大到全量
- 调用超过时限是本补充引入的唯一一类对象齐全时的行为差异

#### AC-VERIFY-LOCAL-07：不支持禁用取回开关的 Git 上同样不连接远端
- **GIVEN** Git 不识别禁用按需取回的开关（早于 2.45）；本地缺少验收要读的对象
- **WHEN** 执行 `openlogos verify --format json`
- **THEN** 传输在建立之前被拒绝：没有与远端建立传输，对象库没有新增对象，结果与 AC-VERIFY-LOCAL-01、02 相同。可能出现一个被启动又被拒绝的 fetch 子进程，不作为失败依据

#### AC-VERIFY-LOCAL-08：不弹出提示，不影响其他命令
- **THEN** 验收期间的 git 调用不弹出凭据或终端提示；`openlogos smoke` 写历史记录时读取提交号与工作区状态的调用、其时限与结果都和 0.16.29 相同

#### AC-VERIFY-LOCAL-09：进入本机全局安装态
- **THEN** 以上行为进入本机全局安装态 0.16.30，并由安装态 smoke 证明（仓内源码修好但安装态未更新不算达成）
- 目标版本就是 0.16.30：装入的是其他版本号时不算达成

### 非目标

- 换一种不读文件内容的方式计算改动文件，使部分克隆下也不回落。
- 验收前自动取回缺失对象。
- 新增原因代码、JSON 字段或配置项。
- 约束 smoke、merge、deploy、branch sync 等其他命令的 git 调用。

### 已知限制

- 早于 2.45 的 Git 靠传输协议白名单拦截远端访问。这条路径只在 Git 2.48.1 上以「只设白名单」的方式验证过，没有在真实的旧版 Git 上执行。
- 部分克隆且本地缺对象的项目，提案验收会回落到全量；想保持按范围验收，需要先让所需对象在本地齐全。
