## MODIFIED — 三层集合与扩大

- **本提案用例**：已合并提案的测试变更集中的 UT/ST。
- **受影响用例**：受影响场景的测试用例文档（`<module>-SXX-test-cases.md`）中全部不带 `[manual]` 的 UT/ST。受影响场景 = 提案「受影响场景」段声明的场景 ∪ 提案 delta 触及的场景。
- **主链路用例**：全部主链路小节所列用例。

提案 delta 触及的场景按文件类别判断：

- **场景文档**：提案 `deltas/` 下有 SXX 的场景文档，SXX 即被触及。
- **测试用例文档**：提案 `deltas/test/` 下有 `<module>-SXX-test-cases.md`，并且这份文档的用例有变化（新增、修改或删除）时，SXX 才被触及。只改「主链路用例」小节、覆盖说明、追溯表等不属于任何用例的内容不算触及。
  - 逐份文档判断：取 `SPEC_MERGED` 合并基线中这份文档的合并前内容，与当前内容比较，比较方式与构建测试变更集相同，每次只比一份文档。不使用整个提案汇总的 `changed_test_ids` / `removed_test_ids`，也不按用例编号归属——从一份文档删除用例（编号可以不含场景号）、或把用例移到另一份文档时，原文档所属场景都被触及。
  - 以下情形按文件名判断（有这份文档的 delta 即被触及）：提案尚未合并；测试变更集无效；没有合并基线，或这份文档的合并前内容读不回、当前内容与合并时写入的不一致。
  - 测试变更集无效时，命令的出口不变：普通提案以 `test_change_set_invalid` 判 FAIL；多切片提案仍由切片清单暂停出口先行返回（`test-slice-manifest-invalid`，需要人处理，不输出 `gate` 与 `layers`）。
- 新列入主链路小节的用例属于主链路层，不依赖所在场景是否被触及。
- 场景未被触及，只表示它不因 delta 进入受影响场景。它的用例仍可能因声明、本提案用例、主链路用例或下面的扩大规则进入验收集合——扩大到全量时，未被触及场景的全部自动化用例照常执行。

完整规则见功能规格 §2.109.5。

只扩大，不缩小：

| 情形 | 扩大到 |
|---|---|
| 没有活跃提案；提案起点不可用；改动命中 `verify.layered.shared_paths`；`logos/logos.config.json` 或 `logos/logos-project.yaml` 中与验收相关的字段（或清单未列出的字段）有变化、或无法判断（按字段判断，只有无关字段变化时不扩大；字段清单见功能规格 §2.96.3.1）；声明写明涉及共享改动 | 全量 |
| 提案没有「受影响场景」段、该段非法或未填写、写了无法评估、声明了不存在的场景 | 按模块（按模块限定范围的结果，并保留声明中已识别的场景与 delta 触及的场景；不可用时为全量） |

声明中的共享标志只要能读出且为真就扩大到全量，即使声明的其余部分不可用。扩大动作本身不直接置 FAIL，也不保证 PASS：门禁按扩大后的最终集合与既有的门禁规则、原因优先级判定；原因写在 JSON `layers.expansion` 与验收报告中。

验收不访问远端：verify 自己启动的 git 调用只读本地对象库、有时限（功能规格 §2.111）。项目是部分克隆且本地缺少提案起点的提交或其中的文件内容时，不从远端取回，按「提案起点不可用」扩大到全量；检查起点或收集改动文件的调用超过时限时同样处理。扩大后按上面的同一条规则判定门禁：没有其他门禁原因时，全部通过则 PASS，因扩大而执行的用例失败则 FAIL。
