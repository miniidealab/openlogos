## ADDED — Windows 公开版原地升级与入口核验

### 场景目标

用户能从已安装的旧版升级，并在新 CMD 键入 `openlogos --version` 时看到目标版本。公开源、镜像和命令入口各有独立证据。

### 操作时序

1. 用户从官网下载可审阅的 Windows 升级脚本并显式执行，传入公告版本。脚本解析本机 npm 与全局 prefix，用 npm 官方源安装精确版本，并检查该 prefix 的 OpenLogos 启动脚本及实际版本。
2. 读取机器及当前用户 Path，按 Windows 的顺序组成新进程环境，执行 CMD 的入口和版本检查。旧入口遮蔽时，在写入前模拟将 npm prefix 移到用户 Path 前方。模拟仍受系统级优先入口或当前目录影响时输出实际入口及可直接调用的目标入口。
3. 模拟成功时持久化当前用户 Path，保留其他目录、环境变量引用及其相互顺序。通知 Windows 环境变更，在重新读出持久化值的新进程中复核实际裸命令与版本。复核失败时恢复 Path 原值。
4. 发布后分别读官方 registry 与 npmmirror 的目标版本及 tarball，记录可下载状态。镜像滞后时继续提供官方源的确定版本命令，可调用镜像现有的同步服务。

### 验收证据

- Windows CI 用真实 npm 和 CMD 验证一次性旧版安装位置上的升级、旧入口遮蔽、用户级修复与无写入的不可修复分支。
- 公网 smoke 核对官方包、官网脚本与真实 Windows 升级证据。镜像状态单独记录供公告使用。
