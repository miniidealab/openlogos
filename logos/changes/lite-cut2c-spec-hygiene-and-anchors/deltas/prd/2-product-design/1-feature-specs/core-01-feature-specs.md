## ADDED — 2.72 章节锚的序数消歧与重复标题检查

### 2.72.0 问题：重复标题使章节永久不可寻址

delta 的章节锚按**标题文本**定位。当同一文档内存在两处文本完全相同的标题时，锚必然解析为 ambiguous；锚解析器只支持祖先路径消歧（`父级 > 子节`），而重复项的祖先链通常相同——于是**该章节以 delta 机制无法寻址**，既改不了也删不掉。

这不是假想。lite-cut1b 至 2b 三刀中撞到四次：`spec/cli-json-output.md`、`spec/change-management.md`、`spec/authority-closure.md` 与功能规格 §2.35 各有一处字节相同的重复 `## ` 标题（历史 ADDED delta 在正文里重复了控制块标题所致）。三次靠「改锚到唯一子节」绕过，代价是留下一批清不掉的空标题壳；一次因唯一可寻址的上级是 1675 行的 H1 而直接放弃。

### 2.72.1 序数后缀

章节锚支持**可选**序数后缀：

```
## REMOVED — <标题> [2]
## MODIFIED — <父级标题> > <子节标题> [1]
```

| 情形 | 判定 |
|---|---|
| 无后缀、同名候选恰 1 处 | 命中该处（与既有行为逐字节一致） |
| 无后缀、同名候选 ≥2 处 | `ambiguous`，诊断点名各候选行号（与既有行为一致） |
| 有后缀 `[n]`、同名候选 ≥ n | 按**文档顺序**命中第 n 处（1 基） |
| 有后缀 `[n]`、同名候选 < n | `not_found`，诊断说明实际候选数 |
| 有后缀但候选恰 1 处且 n=1 | 命中该处 |

序数在**同名候选集合内**计数，与文档中其它标题无关；候选集合先经路径锚过滤（若锚含 ` > `），再按序数选取。

**兼容性**：不带后缀的锚行为完全不变——本能力只增不改。

### 2.72.2 lint-specs 增加重复标题检查

`openlogos lint-specs` 增加第四个检查项 `duplicate_heading`：同一文件内出现两处及以上**文本完全相同**的标题即报告，逐条列出各出现行号。

重复标题的后果（章节不可寻址）比重复 ID 更严重却更隐蔽——重复 ID 会让一个验收结果被静默覆盖，重复标题会让一整节永久失去可维护性。与其余检查项一致，本项**不参与任何门**，仅供人判断。

## ADDED — 2.73 L8 条目守恒降级为警告

### 2.73.0 判据与强度的分离

L8 检查「delta 的 MODIFIED 块是否隐式删除了目标章节的既有结构化 ID」。判据本身有价值——它确实能发现无意的删除——但把它做成**阻断门**的成本高于收益：

- 守恒的真正判据是「删掉的 ID 是否还有测试在跑」，那是**运行期事实**，由 `openlogos verify` 的孤儿结果检查天然覆盖：规格删了 ID 而测试还在跑，verify 判 result ledger 不一致。
- L8 的静态对账对区间引用（`UT-S05-47～UT-S05-50` 这类散文写法）等形态会产生误报，本次减法中多次拦下并无问题的 delta。

### 2.73.1 强度调整

| 码 | 调整后 |
|---|---|
| `delta_implicit_id_removal` | **警告**——出现在 `warnings`，不计入 violations、不影响退出码 |
| `delta_removed_unknown_id` | **警告**——同上 |
| `delta_section_anchor_unresolvable` | **保持违规**（见下） |

`merge` 不再因条目守恒拒绝合并；诊断内容与定位精度**逐字不变**，只改变严重度分级。

### 2.73.2 为什么 anchor-unresolvable 不降级

它不是守恒判断而是**定位失败**：锚解析不到章节时，`composeOpenLogosMarkdown` 在合成阶段必然 fail-closed。把它降级只会让用户更晚、在更差的位置（merge 中途而非 lint 时）看到同一个错误，没有任何收益。

- 测试：UT-S37-41、ST-S37-11、UT-S35-137。
