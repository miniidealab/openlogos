## 三、测试数据与断言要求

- 一次性仓库与其中的全部文件在用例结束后删除；不访问网络，不配置真实远端（需要远端默认分支的用例以本地裸仓库充当 `origin`）。
- 「零改动」以执行前后项目全部文件、git 索引（`git ls-files -s`）与各分支指向的 SHA-256 比对取证，不以「命令报错」代替。
- 「取主分支版本」以文件字节与 `git show main:<path>` 的输出逐字节比对取证；「未写回」以登记表字节与同一构造下纯 `git merge --no-commit` 的结果比对取证。
- 条目合并的纯函数用例（UT-S44-05～UT-S44-09）直接传入解析后的三个版本，不经过 git；其余用例经真实 CLI 进程执行。
- 中途失败（UT-S44-18、ST-S44-05 ④）、取锁前后的交错（UT-S44-14 ⑤⑥）与 git 拒绝（UT-S44-27）使用进程内注入点，不依赖时序竞争或磁盘故障。
- 「本地文件未被覆盖」以未入库文件执行前后的 SHA-256 比对取证；这类文件不在任何提交中，不能用 git 对象比对代替。
- 结果以 JSON 中的结构化字段断言，不解析人类可读文案；文案只在 UT-S44-25 中断言，中英文各至少覆盖一个错误码。
- 基线运行夹具的提交记录、运行记录与锁文件按 `baseline-seed-txn.ts` 的真实格式构造或由真实命令产生，不手写近似结构。
