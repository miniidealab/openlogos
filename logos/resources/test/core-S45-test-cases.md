## 三、测试数据与断言要求

- 一次性仓库与其中的全部文件在用例结束后删除；不访问网络，不配置远端。
- 「零写入」以执行前后项目全部文件与 git 索引（`git ls-files -s`）的 SHA-256 比对取证，不以「命令报错」代替。
- 流程判定以 JSON 中的结构化字段（`violations[].code`、`violations[].path`、`warnings[].code`、`pass`、退出码）断言；`message` 只做「包含两个来源路径 / 包含 ID」之类的包含性断言，不据其反推流程结果；需要结构化比对两个来源时，在纯函数用例中断言视图的重号解析结果。violation 对象沿用 §3.15 的 `code` / `path` / `message` / `fix_hint`，不读取契约未定义的字段。
- 跨分支用例（ST-S45-02～ST-S45-04）以真实 git 分支与合并构造，不手工拼接最终文件；合并阶段用例（UT-S45-16～UT-S45-18）以真实 `merge` 与修正流程构造 `SPEC_MERGED` 与合并基线，不手写近似结构。
- 条目解析与视图构建的纯函数用例（UT-S45-02、UT-S45-03）直接传入文件内容，不经过 CLI 进程；其余用例经真实 CLI 进程执行。
- UT-S45-10 的基线由同一夹具在实现前的 CLI 版本产生并作为 golden 固化。
- 直接录入用例（UT-S45-21～UT-S45-43、ST-S45-06～ST-S45-10）的候选目录一律以 `mktemp -d` 建在项目根之外（UT-S45-22 ⑤ 除外），用例结束删除；「零写入」以执行前后项目全部文件与 git 索引的 SHA-256 比对取证。
- `knowledge` 命令组的判定以 JSON 结构化字段（`data.result`、`data.written[]`、`errors[].code`、`errors[].path`、`warnings[].code`、`data.tag_state`、`data.head_compare`、退出码）断言，不据 `message` 反推结果；JSON 契约见 `spec/cli-json-output.md`「`openlogos knowledge` 命令组」。
- 事务故障与并发用例（UT-S45-38、UT-S45-41、UT-S45-43）通过批次提交原语的测试钩子注入（UT-S45-41 用文件屏障控制首个子进程的停顿与放行，等待时限可经测试参数缩短），不依赖真实断电；「回滚完成前不当作已接受内容」以各命令的退出码与 `errors[].code` 断言。
- 标签表三态的纯函数用例（UT-S45-26）直接传入文件存在性与 HEAD 读取结果，不经 CLI 进程；HEAD 相关夹具以真实 git 提交构造。
- guard 用例（UT-S45-34）复用既有 guard 测试夹具，以 hook 输入 JSON 驱动托管的 `guard-check` 与 `guard-post-check.cjs`，不依赖真实宿主。
- UT-S45-33 ④ 与 UT-S45-36 ③ 的基线由同一夹具在实现前的 CLI 版本产生并作为 golden 固化。
